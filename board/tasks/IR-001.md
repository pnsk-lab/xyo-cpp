## Scope

LLVM・Binaryenの両方が使用するスケジューラ所有のCallFrameと戻り先PCを定義する。再帰・引数・戻り値を保存し、yieldをまたいで再開可能にする。

## Acceptance criteria

- [x] CallFrameにprocedure ID、return PC、引数、SSAローカルを持たせる
- [x] LLVMとWASMが同一のフレーム契約を検証する（同じABIレイアウト・検証用ビット列、および実行時の戻り先）
- [ ] 非warp・再帰と複数return siteのパリティを追加する（LLVM native FiberとWASMの実経路は別々のため継続）
- [ ] 任意の非warp手続きをFiber非依存でyieldから再開できる
- [ ] GCルート管理されたValue引数に対応する（LLVM native mirror: 文字列引数対応済み。Fiber非依存実行とWASM側の一般Value復帰は継続）

## Files / dependencies

src/ir/execution_abi.hpp, src/ir/scratch_transfer.hpp, src/jit/, src/wasm/
Dependencies: RT-001; coordinate with IR-002.

## 実装進捗（agent-common-ir）

- scheduler所有の共通CallFrameAbiとScratchCallStackを実装した。
- ScratchProcedureTableで捕捉済みScratchTransferGraphのprocedure定義を再現可能な整数IDへ変換する。
- フレームはprocedure ID、return PC、resume PC、引数数、SSA-local数、引数ビット値、SSA-localビット値を保持する。
- 数値フレームの上限検証、再帰呼び出しと復帰、yield跨ぎでの保存、推測的変更のcommit/discard、stale commit拒否を実装。
- Binaryenのwarp非末尾再帰も同じCallFrameAbiフレーム配置を用いるよう移行。
- LLVM通常JITへ実引数/戻り先PCを格納する試験的ブリッジを接続済み。Fiberが実際の復帰命令位置を保持するため、Frame単体での再開は未完成。RT-001との統合を継続し、IR-001はin_progressを維持。

検証：
- Native C++ / Emscripten WASM同一コードのCallFrameテストでdigest一致。
- xyo-call-frame-abi-smoke、xyo-numeric-ir-smoke、xyo-ir-cfg-backendsは3/3成功。
- wasm_return_pc_stack.pyは10/10成功（5方式比較）。
- common_cfg_backend_parity.pyは28/28成功（テスト拡張後の単独再実行）。
- ScratchBenchのInterpreter/builtin/Binaryenで2123/2123の出力一致。
- ログ: scratch-bench/results/agent-board-*.log。

次：LLVM側の手続き実行時にもscheduler所有のCallFrameを接続し、非warp再帰・yield跨ぎ復帰を検証する。既存の高速経路を保持する。


## LLVM JIT実経路の進捗（2026-11-08）

- opt-in XYO_JIT_CALLFRAME=1でLLVMコード生成が引数を1度評価してnative CallFrameヘルパへ渡し、通常の手続き呼び出し/復帰を観測する。デフォルトのJITには追加呼出しを生成しない。
- src/jit/procedure_frame_state.hppが捕捉済みIRからcallsite→callee、return PC、entry PCを確定し、scheduler所有のScratchCallStackでフレームを管理する。
- 数値引数だけフレームに保存し、文字列/リスト等GC管理引数はmirrorを安全に無効化して通常のLLVM実行を続ける。
- xyo_yield()のFiber中断前と復帰後でframe深さ・世代・検証結果の不変を確認する。
- 引数バッファはLLVM関数入口で一度だけ確保するため、同じcallsiteを数万回実行してもFiberスタックが累積増大しない。
- テスト: native_callframe_mirror.py 7/7、native_callframe_fuzz.py 16/16、native_callframe_stress.py 20,000反復+外側の手続きで20,001 calls/returns一致。
- 既存 CTest 6/6、WASM PC stack 10/10、共通CFG 28/28、ScratchBench全2123出力一致。
- 詳細: docs/native-llvm-callframe-bridge-2026-11-08.md。
- 重要: これはfiber上の本物のcallに結びついた論理CallFrameであり、LLVM実行器をFiber非依存に変える最終統合ではない。RT-001の実行PCとIR-002のGC-safe ABIが必要。


## Source-loop checkpoint integration (2026-11-08)

- Native LLVM fast nonwarp yield previously bypassed the CallFrame
  observer; only XYO_JIT_CALLFRAME=1 now routes that edge through the
  full host yield bridge. Default native path remains unchanged.
- LLVM lexical loop lowering records stable Scratch source loop IDs,
  and captures the exact predecrement counter for a counted repeat in
  the corresponding CallFrame local.
- Each captured lexical loop is assigned a distinct local slot, up to
  32 loops per program; nested outer and inner counters no longer
  overwrite each other. The source-level PC is not the machine PC.
- Fixed Interpreter/native/native+Frame parity is now 8/8, including
  96 actual nested yields and sum180 across 96 exact counter snapshots.
  Basic nonwarp repeat has 36 yields and counter sum72.
- Bounded recursive fuzz 32/32; repeated procedure 50,001/50,001
  calls/returns with matching ordinary LLVM result.
- Details: docs/native-llvm-callframe-bridge-2026-11-08.md and
  scratch-bench/results/agent-ir001-loopslots-*.log.

This is still a runtime mirror, not Fiber-independent LLVM execution.
Remaining IR-001 blockers: arbitrary SSA frame restoration on deopt,
complete active loop nesting/branch PC recovery, and IR-002 GC handles.

## Full lexical loop path checkpoints (2026-11-08)

- LLVM native CallFrame's opt-in yield checkpoint now publishes the
  full active outer-to-inner lexical loop path in one helper invocation.
  Previously, a nested inner loop's yield did not capture the outer loop's
  private remaining counter at that same scheduler boundary.
- CallFrame local layout for N lexical loops is: N individual counter
  slots; N ordered source-loop-PC path slots; 1 raw integer depth slot.
  Missing/noncounted counters retain kNoLoopCounter, inactive path entries 0.
  N<=32; other scripts fail closed for observer only, ordinary JIT preserved.
- NativeProcedureFrameSession::sourceCheckpoint() exposes procedureId,
  returnPc, resumePc and full ordered active loop counters as pointer-free
  data, and beforeYield() verifies this representation for actual Fiber yields.
  The scheduler can consume it without reading LLVM machine registers.
- Tests: native_callframe_mirror.py 11/11, including 3 nested repeat levels
  (168 yields, 240 parent snapshots, parent sum 360), 2-level nested
  (96 yields, 72 parent snapshots, parent sum 108); seeded recursion 32/32;
  CTest 6/6 at this stage.
- Remaining: arbitrary SSA recovery, nested branch/effect positions,
  host side-effect commit continuity, and a Fiber-independent continuation
  executor. This is verified observation and serialization, not restoration.
- Files: src/jit/procedure_frame_state.hpp, src/jit/codegen.cpp,
  src/jit/rt.cpp, src/jit/backend_llvm.cpp,
  tests/differential/native_callframe_mirror.py,
  docs/native-llvm-callframe-bridge-2026-11-08.md.

## Full rooted procedure-chain handoff (2026-11-08)

- NativeProcedureFrameSession::exportContinuation() clones all current
  logical frames into independently owned RootedScratchCallStack. All
  procedure/return/resume PCs and published loop locals transfer without
  exposing raw GC pointers to numeric frame words; each argument is
  independently rooted by the new GC provider.
- Export fail-closes on mismatched child return PC vs caller resume PC,
  bad image/sidecar depth, corrupted argument placeholders, invalid
  frame arity/local capacity, or unsuccessful copy. matchesExport()
  verifies the complete source vs exported image at safe points.
- LLVM procedure call emission now checkpoints its caller loop path
  before entering a child; previously parent counters were stale at
  recursive callee yields. Added opt-in
  XYO_JIT_CALLFRAME_EXPORT_PROBE=1 to clone/verify every real yield
  and expose exports, max_export_roots, max_export_depth and
  ancestor_loop_frames in diagnostics.
- Tests: native_callframe_mirror.py --export-probe 13/13 including
  recursive calls inside nonwarp repeat (84 calls/returns, 240 yields,
  parent loop frames retained); seeded recursive fuzz 32/32;
  callsite stress 50,001/50,001; native CTest 7/7.
- This is still a rooted handoff image, not LLVM Fiber-independent
  execution: register SSA, intermediate conditional/effect PC, and
  interleaved side-effect commit across deopt are not yet reconstructible.
  Snapshot consumers must also verify compatible captured source revisions.
- No commit or push; other agents' changes remain untouched.

## Distinct callsite return PCs and independent symbols (2026-11-08)

- Replaced source block.next-based call return PC (which collapses
  terminal callsites) with a deterministic synthetic after-call PC per
  resolved Scratch callsite. Each has a SourceReturnSite mapping:
  NextBlock, AfterBranch, LoopLatch, ProcedureExit or ScriptExit, and
  exact source call/target PCs.
- Structural parent walking distinguishes previous linear siblings
  (parent.next==child.id) from actual conditional/loop nesting. Return
  sites are stable across source graph iteration order and disjoint
  from ordinary block PCs.
- SelfContainedSourceContinuation now owns RootedScratchCallStack AND
  an immutable shared SourceFrameSymbols dictionary for block names,
  procedure IDs and synthetic after-call PC decoding. The bundle does
  not need NativeProcedureFrameSession or Fiber to resolve source IDs.
  Previous exportContinuation() interface remains compatible.
- Native LLVM opt-in probe checks the bundle at each real yield,
  including known return-site target, nested procedure mapping,
  parent resume-PC and independent heap roots.
- Fixed test cases: 18/18 (5 new return-site kinds and multiple lexical
  calls to same callee), with Interpreter/LLVM/mirrored LLVM parity.
  Full SSA/environment reconstruction remains RT-001's pending work.

## Source-level execution phase contract (2026-11-08)

- Added src/ir/source_resume_phase.hpp and a final local for the native
  CallFrame's explicit execution phase: 2*N+2 locals for N lexical loops.
  The same source loop+counter can be recorded before a nested call
  (InsideLoopBody) or after a completed iteration (AfterLoopBody); they
  are no longer incorrectly conflated.
- enter() initializes ProcedureEntry; parent transitions to
  AwaitingCallee; bodyStarted() marks UnknownBody before LLVM callee
  executes; leave() sets parent AfterCallee. A source loop checkpoint
  records its explicit body-completion phase.
- Updated xyo_proc_frame_checkpoint_path_phase and
  xyo_proc_frame_body_started opt-in JIT runtime symbols; default native
  JIT/AOT unchanged.
- SelfContainedSourceContinuation::decodeFrames() returns typed source
  control descriptors, including PC, return-site kind, ordered
  loop counters and phase. It keeps string arguments in the separate
  rooted owner and rejects invalid per-loop/phase state.
- Native export probe checks leaf vs decoded phase/loop state and that
  nonroot ancestors are AwaitingCallee; diagnostics report per-phase
  yields and parent wait-depth counts.
- native_callframe_mirror.py --export-probe passes 19/19. New
  nonwarp_wait case demonstrates a real wait yield as UnknownBody
  (not an unsafe ProcedureEntry). Scheduler-native handoff 5/5.
- No arbitrary SSA/effect restoration or independent executor exists
  yet. The new phase prevents accidental unsafe handoff, but does
  not certify executable deoptimization.


## Immutable compiled-source revision guard (2026-11-08)

- Added sourceRevision to shared ScratchCompilationUnit, captured from
  Blocks::revision and rejected if capture races a structural source edit.
  LLVM lowering verifies the revision before and after code emission.
- New xyo_proc_frame_enter_rev ABI bakes compile-time source revision
  into every opt-in procedure callsite. NativeProcedureFrameSession stores
  compiled revision/Blocks identity and rejects entry, yield, and export
  if the live revision differs. Legacy no-revision frames are
  observation-only, not eligible for interpreter handoff.
- SourceFrameSymbols carries the original revision independent of the
  Fiber. RT-001 can reject stale source even if block IDs match.
- New CTest xyo-native-callframe-revision-smoke covers pre-entry mismatch,
  post-entry source edit, legacy rejection, successful fresh version, and
  an independently GC-rooted Unicode string after source session
  destruction and forced GC.
- RT-001 test-only post-yield resetCache hook verifies rejection of stale
  native-to-interpreter deopt, not merely a synthetic unit test.
  Latest native_simple_resume.py: 71/71 actual adoption/refusal parity.
- Source guard deliberately does not certify general SSA/effect resumption;
  direct writes to Blocks without normal revision invalidation are outside
  its validity contract.
- Shared worktree preserved; no commit/push.

## Same-revision source content guard (2026-11-08)

- native_callframe_revision_smoke tests direct Block opcode, field,

- Runtime default path remains unchanged and full source comparison

## Strict loop-scoped caller validation (2026-11-08)

- SourceReturnSite::callerLoopPath is compiled from verified lexical

## Source statement ownership proof (2026-11-08)

- SourceFrameSymbols::statementOwners is a compact vector indexed by
  immutable source PC: real executable source procedure ID, root=0,
  or kNoPc for unverified/non-executable nodes.
- Owners are resolved once in O(N+E) from the root and verified
  procedure entries by following valid NEXT and SUBSTACK/SUBSTACK2
  parent-linked edges. No quadratic per-block parent rescans.
- NativeProcedureFrameSession::statementStarted checks current
  procedure ownership; enter() checks callerProcedureId before
  mutating frames or GC roots. Detached image.valid() also checks
  the returned callsite source owner.
- A 2,048-element NEXT chain regression proves that root-owned source
  statements do not get mixed with a separate source procedure, and
  that the prototype stays unexecutable. The test uses immutable
  source-symbol ownership even after native continuation export.
- C++ regression accepts a genuine statement and rejects sibling
  procedure statements, prototype PCs, and a root call from a child.
- Opt-in only. RT-001 owned handoff files were not modified.


## Source post-call successor validation (2026-11-08)

- The RT-owned effect-commit and executable reconstruction remain

## Exact source return edge (2026-11-08)
