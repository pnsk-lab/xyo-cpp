# PHI需要解析：最適化後LLVM IRとネイティブコードの計測（2026-11-07）

## 計測方法

`tests/bench/phi_demand_metrics.py` を追加。

```sh
python3 tests/bench/phi_demand_metrics.py --runs 5
python3 tests/bench/phi_demand_metrics.py --runs 3 \
  --projects tests/bench/algos/out/bubblesort_500.sb3 \
             tests/bench/algos/out/sha256_16384.sb3
```

既存のJIT計測機構を再利用する。

- `XYO_JIT_TIMING=1`：IR生成、LLVM最適化、ORC投入、シンボル解決・機械語生成の時間を個別取得
- `XYO_JIT_DUMP2=1`：**最適化後**のLLVM IRを出力、PHI数を実測
- `XYO_JIT_DUMP_OBJECT=<prefix>`：ORCが生成したネイティブオブジェクトを保存して、binutils `size -A`で`.text`を計測
- `objcopy`がある場合は`.text`のSHA-256も採取できる。ただしランごとの埋め込みアドレスや再配置でハッシュが変わり得るため、ハッシュの差を機械語命令列の差と断定してはいけない

**計測用実行とIR/オブジェクトの検査用実行を分離**し、巨大なIRのダンプによってコンパイル時間が歪まないようにした。各モードでウォール時間とJIT内訳の中央値を採り、起動・SB3読込・変数JSON出力を含むウォール時間と区別する。

比較条件：eager LLVM/O3、GPUと並列実行を無効化、混合型の遅延SSA有効。3方式は `baseline`（IF PHI無効）、`all_phi`、`demand`（合流後の需要解析有効）。

## 実測

6ケース、各モード5回のコンパイル時間中央値と、最適化後のコードサイズ：

| SB3 | baseline JIT ms | all_phi JIT ms | demand JIT ms | 最適化後PHI数（全方式） | .text bytes（全方式） |
|---|---:|---:|---:|---:|---:|
| 専用warp混合型 | 80.99 | 79.31 | 80.34 | 180 | baseline 15,569 / all_phi・demand 15,178 |
| quicksort_4000 | 136.76 | 133.62 | 134.51 | 353 | 28,355 |
| mergesort_4000 | 108.97 | 108.38 | 108.25 | 304 | 24,307 |
| sieve_100000 | 81.76 | 82.93 | 82.29 | 191 | 16,818 |
| fib_27 | 20.03 | 20.02 | 19.91 | 25 | 3,827 |
| micro_loop_1000000 | 15.21 | 14.95 | 15.01 | 20 | 3,014 |

追加3ケース（各3回）：

| SB3 | baseline JIT ms | all_phi JIT ms | demand JIT ms | 最適化後PHI数 | .text bytes |
|---|---:|---:|---:|---:|---:|
| bubblesort_500 | 83.36 | 82.90 | 83.53 | 229 | 18,099 |
| sha256_16384 | 148.34 | 144.98 | 146.82 | 264 | 37,715 |
| micro_read_1000000 | 31.95 | 31.51 | 33.20 | 63 | 6,086 |

同じSB3内の決定的な結果チェック値はすべて一致した。

### 解釈

- 以前の専用フィクスチャでは**最適化前**のPHIが45→30（−33%）になった。
- しかし、今回計測した9ケースすべてで `all_phi` と `demand` の **最適化後のPHI総数とネイティブ .text サイズは同じ**。LLVM O3が不要なPHIを既に消している可能性が高い。
- PHI生成自体を有効化した専用フィクスチャでは、baselineと比べて .text が391バイト（約2.5%）減少したが、ほかの8ケースではコードサイズが変わらなかった。
- 2〜5回の総実行・コンパイル時間の数ms差は測定誤差と区別できず、一般的な高速化は実証できていない。
- このため `XYO_JIT_IF_PHI` と `XYO_JIT_PHI_DEMAND` はともに**既定OFF**を維持する。

## コード生成コスト削減

`src/jit/codegen.cpp` の需要解析呼び出しに事前条件を追加。昇格ループではない分岐、合流できない分岐、両経路に同一変数の有効なSSA候補がない分岐では、最大32命令/256レポータの需要解析を最初から走らせない。これは処理時間を改善する可能性があるが、パフォーマンスの定量的改善を保証するものではない。

## PHI候補数を直接計測（続編）

`XYO_JIT_PHI_STATS=1` を有効にすると、IR生成時に以下の診断行が追加される。

```
[jit-phi] SCRIPT merges=... demand_scans=... candidates=... boxed=... boxed_skipped=... numeric=... numeric_skipped=...
```

これらは生成コード内の命令ではなく、**JITコンパイル時のみ**の計測。計測スクリプトもこの値をJSONに収集する。実行時間測定とは分離したIR検査実行で取得するため、標準エラー出力を増やしてコンパイル時間を歪めない。

測定結果（`build/phi-opportunity-metrics.json`、各方式3回）：

| SB3 | 方式 | 候補数 | boxed生成 | boxed省略 | 数値PHI生成 | 数値PHI省略 |
|---|---|---:|---:|---:|---:|---:|
| 専用warpフィクスチャ | 全生成 | 25 | 25 | 0 | 20 | 0 |
| 専用warpフィクスチャ | 需要解析ON | 25 | 20 | 5 | 10 | 5 |
| quicksort_4000 | 全生成・需要解析ON | 0 | 0 | 0 | 0 | 0 |
| mergesort_4000 | 全生成・需要解析ON | 0 | 0 | 0 | 0 | 0 |

後半の実ベンチマークではPHI候補そのものがゼロで、需要解析によりLLVMの生成コードを削減できる余地がない。性能値の僅差は計測誤差や環境条件に左右されるため、需要解析の一般的な高速化とは解釈しない。

## boxed値の見かけ上の同一性

同じ数字を持つScratchのシャドウブロックでも、内部では独立した文字列オブジェクトへの参照が格納されるケースを確認した。これらのboxed値は整数ビット列として異なり、数値として同じだからといって型タグ付きSSAを統合することはできない。試験的なSSA値同一判定のPHI省略は適用機会が確認できず撤回した。フィクスチャにはこのケースを残し、インタプリタとの結果一致を検証する。

## 既存CTestの再検証

最初の全CTest（41件）は10件が`build/xyo`起動時に`PermissionError: [Errno 13]`で失敗した。ビルド後の直列再実行では、当該10件すべてが別々の試行で通過した。これは一時的なプロセス起動環境の問題と整合するものの、原因を特定したわけではない。全スイート41/41の一括成功とは記録しない。

## 最終検証（リテラル同一性ケース追加後）

同じ数値文字列を別々に生成する分岐を差分テストに追加した。
Scratchの文字列値は独立したポインタを持つことがあり、
\`Value*\`が異なるからといって単なる値の等価性だけでPHIを
省略してはいけない。試験的な同一SSA省略パスは撤回した。

\`build/phi-opportunity-final.json\`（各モード2回）の集計：

| SB3 | 方式 | PHI候補 | boxed省略 | 最適化後PHI総数 | .textバイト |
|---|---|---:|---:|---:|---:|
| 改訂済み専用warp | baseline | 0 | 0 | 216 | 18,412 |
| 改訂済み専用warp | all_phi | 30 | 0 | 216 | 18,596 |
| 改訂済み専用warp | demand | 30 | 5 | 216 | 18,596 |
| quicksort_4000 | all_phi | 0 | 0 | 353 | 28,355 |
| quicksort_4000 | demand | 0 | 0 | 353 | 28,355 |

専用フィクスチャの変更により上の数値は本書冒頭の古い
フィクスチャの測定値と異なる。性能比較では**同じ版のSB3**
で測定した値同士だけを比較すること。

再ビルド後の関連CTest（単体、遅延型SSA、型変化生成テスト、
if-PHI、OSR）は **5/5成功**。
