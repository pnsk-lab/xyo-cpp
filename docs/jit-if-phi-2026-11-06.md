# Flow-sensitive `if` false-edge SSA forwarding (2026-11-06)

## Implementation

In `src/jit/codegen.cpp`, mixed-type promoted variables can now retain
their boxed SSA producer on a plain `if`'s **false path**, where no
assignment takes place. When the true path writes the same variable, the
join constructs `typed.if.bits = phi i64`. The previous `if-else` code
only forwarded a variable if both sides wrote it.

The proof is deliberately narrow:

1. The variable must have an active lazy typed SSA shadow within a
   promotable loop, with unambiguous variable IDs.
2. The previous write must have occurred in the LLVM basic block **at
   the start of condition evaluation**.
3. The entire condition expression must consist of explicit,
   read-only reporters; malformed graphs, unknown opcodes, procedures,
   extension callbacks, and opaque host operations are rejected.
4. The true path and false path must reach the join, and their incoming
   boxed values must dominate their respective predecessors.
5. A numeric `typed.if.number = phi double` is constructed only if both
   boxed producers already carry an exact Scratch `toNumber` fact and a
   corresponding numeric comparison eligibility value.
6. When both eligibility operands are the **same SSA value** (including
   constant `true`), reuse the value directly without an unnecessary
   `i1` PHI. Otherwise preserve the dynamic eligibility PHI.
7. No value facts survive an unknown call, yield/reload or OSR handoff.
   The original shadow, runtime coercions and boxed semantics are kept.

### Feature flag

`XYO_JIT_IF_PHI=1` enables this optimization, and
`XYO_JIT_IF_PHI=0` (or unset) disables it. This new optimization
defaults **OFF** until general-workload performance is established.
`XYO_JIT_LOCAL_VAR_FORWARD=0` also disables its prerequisites.

## Validation

`tests/differential/jit_if_phi.py` generates warp/non-warp Scratch
programs with mixed string/number storage, true and false `if` paths,
numeric consumers, and loops spanning 0,1,2,65,129 iterations. For
each program it compares the interpreter with eager JIT (OFF/ON),
HotSpot, JIT O2, and diagnostic IR dumping. The original 10 JIT comparisons passed; the final suite also covers the default-OFF configuration (12 total JIT comparisons).

`XYO_JIT_DUMP=1` verifies `typed.if.bits` and
`typed.if.number` PHIs and shows that the number PHI feeds numeric
arithmetic. In a representative unoptimized fixture, the compiler
generated 25 matching `typed.if.number` uses and **zero** redundant
`typed.if.cmpok` PHIs because the eligibility proof was equal on
both incoming paths.

The six focused CTest suites previously passed:
`xyo-jit-lazy-typed-ssa`, `xyo-jit-type-flow-safety`,
`xyo-jit-cfg-type-hints`, `xyo-jit-type-flow-fuzz`,
`xyo-jit-if-phi`, and `xyo-jit-ssa-scheduler`.

### A/B timing caveat

These are wall times including startup, SB3 loading and compilation;
each setting was executed three times, alternating OFF/ON.

| Project | OFF median | ON median | Output parity |
| --- | ---: | ---: | --- |
| Dedicated warp IF fixture | 0.0714 s | 0.0696 s | matched |
| Dedicated nonwarp IF fixture | 0.0690 s | 0.0700 s | matched |
| quicksort_4000 | 0.1549 s | 0.1562 s | matched |
| mergesort_4000 | 0.1291 s | 0.1327 s | matched |
| micro_read_1000000 | 0.0486 s | 0.0482 s | matched |

There is no reliable general speedup from these small timing samples.
Do not call the synthetic fixture's improvement a performance gain on
arbitrary Scratch projects.

## Future work

Use a larger independent SB3 corpus, track compiler time and generated
IR size separately, and consider using numeric demand at branch join
sites to avoid unnecessary PHIs. Further guard elimination must respect
dynamic types, NaN, whitespace-only numeric strings, other scripts'
writes and GC/yield boundaries.
