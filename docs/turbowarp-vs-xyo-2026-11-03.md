# xyo-cpp HotSpot JIT と TurboWarp compiler の実機比較（2026-11-03）

## 条件

- ホスト Intel Core i7-12700、Linux、両プロセスとも `taskset -c 12`。
- ScratchBench の同一 `performance.sb3`（47項目）。全カーネルの総実行時間のチェックではなく、各カーネル内の `ops/ms` を比較する。
- xyo-cpp: 2026-11-03の作業ツリーからビルドした `Release`（`XYO_DISABLE_RT_PROF=ON`）。`build/tw-compare-current-xyo` に固定（SHA256 6730470cb75a203fd4469f18981461c6d55f35bb2681267f6215f32f6f618915）。HotSpot JIT有効。SB3コマンド `run --jit hotspot --fps 30 --print-list output`。
- TurboWarp: ScratchBenchにインストールされた `turbowarp-vm`、VMコミット `f26ff67e951258a84d25cad3acaf8804eb202318`（従来の記録では `2.1.46+f26ff67`）。`BENCH_COMPILER=1 node runtimes/node-vm.mjs turbowarp .cache/build/performance.sb3`。
- 3回ずつ、プロセス順を `xyo→TW / TW→xyo / xyo→TW` と交互に変更。同じランタイム・項目の3回 `ops/ms` **中央値**を算出し、`xyo中央値/TurboWarp中央値` を比較する。
- 3回とも両者で47項目完走。実時間依存の `sched_*` 8項目を除く39項目は、すべての実行で両者のチェックサム一致。

## 概観

- 全39項目を等重みとした速度比の幾何平均は **1.122倍（xyo/TurboWarp）**。
- xyoの勝ちが **23/39**、TurboWarpの勝ちが **16/39**。
- これはScratchBenchの固定項目を等重みとする統計量であり、一般的なScratchプロジェクト実行時間が12%速いという主張ではない。

## 測定上の注意

TurboWarpの初回実行は壁時計で約89秒かかり、そのうち一部のループ・算術・変数項目が異常に遅かった（例: `vars_many` 約119 ops/ms に対し、2回目・3回目は約7.3万〜7.5万 ops/ms）。そのため**初回の単純平均を使うとxyoの相対速度を大幅に過大評価する**。本表では各項目3回中央値を使った。対照として異常のない2回目と3回目だけの中央値では幾何平均 **1.149倍**、39項目の3回中央値では1.122倍だった。

一部のTurboWarp項目（`str_join`、`list_append` 等）は2回目と3回目の差も比較的大きい。限られた3回のベンチのため小さな優劣（±数%）は断定しない。JITコンパイル・起動の時間は `ops/ms` に含まれない。異なるランタイムのメモリ使用量や起動時間は、この測定方法では比較していない。

## 次の最適化候補（ベンチ固有の特化は行わない）

1. `str_join` は xyo が **0.352倍**。cons stringのノード確保・GC・フラット化タイミングを一般の文字列ワークロードでもプロファイルする。専用consプールの以前の試作は悪化しているので繰り返さない。
2. `math_arith` は **0.582倍**。剰余（定数除数・可変除数）で `f64→i32→f64` の往復・整数性判定・0/+∞/NaN対応の分岐が残る。型/値域が証明できる範囲でSSA上の整数表現を維持することを検証する。
3. `app_ast` は **0.626倍**。動的演算・文字列・参照を別々にプロファイルして原因を特定する（現状は仮説）。
4. `list_append` は **0.716倍**だが `list_read` は **1.489倍**。リスト全体の弱さではなくappend専用の確保/拡張/書込み経路を調査する。
