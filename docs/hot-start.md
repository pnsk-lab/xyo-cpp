# 実行状態の保存・復元（Hot Start）

`xyo-cpp` の **Hot Start** は、Scratch プロジェクトの実行中の
スレッド・変数・クローン・描画状態などを `.xyhot` ファイルに保存し、
別プロセスでもそこから再開する機能です。`.sb3` の通常保存とは異なります。

## 使い方

```sh
# 8フレーム実行して状態を保存、そこで終了
./build/xyo run game.sb3 --hot-save game.xyhot --hot-save-frame 8

# 以前の続きから実行。--frames は「追加で実行するフレーム数」
./build/xyo run game.sb3 --hot-load game.xyhot --frames 100

# ウィンドウで再生して、F5 を押した時点で保存（再生は継続）
./build/xyo play game.sb3 --hot-save game.xyhot

# ウィンドウで以前の続きから開始
./build/xyo play game.sb3 --hot-load game.xyhot
```

`--hot-save` のみ指定した場合、`run` は終了時に保存し、
`play` は F5 キーおよび再生終了時に保存します。`--hot-save-frame N` と併用すると、
Nフレーム後に保存して終了します。

保存・復元のフラグを使うとJITは自動的に `--jit=off` 相当へ切り替わります。
Scratch のインタプリタの各フレーム境界でのみ保存します。
ネイティブ JIT のファイバスタックを直接シリアライズすることはありません。

## 保存するもの

- スレッドの実行位置、再帰呼び出しフレーム、引数、部分評価済みの式と制御フローの状態
- 変数・リスト（NaN、真偽値、文字列なども型を保って保存）
- スプライトの位置・向き・大きさ・コスチューム・見た目・クローンと描画順
- Scratch タイマー、待機中のタイマー、乱数生成器の状態
- ペン画像（CPU・OpenGL・高画質ペン）、ペン色やペンダウン状態
- 音声（再生待ち／デコード待ちの音源、再生位置、待機スレッド）

## 制限

- **保存時と同じ `.sb3` を使う必要があります。** 元のSB3のバイト列に
  対する指紋をチェックします（同じ内容でも再圧縮で一致しない場合があります）。
- 保存形式はバージョン付きJSONです。現在はバージョン1。
  異なる実行環境での永続的なバイナリ互換性は保証しません。
- `sensing_askandwait` の入力待ちや、保存に未対応の外部 Promise を
  待機している場合はエラーにします。保存が失敗した場合に
  部分的なセーブデータを完成扱いしません。
- 音声を保存したセーブデータは音声デバイスが必要です。
  復元時に音源の再デコードが発生する場合があり、サンプル単位の
  完全同期を保証するものではありません。
- ネイティブ機械語、SDLのリソースハンドル、GPUテクスチャIDは保存しません。
  ペン画素や音声位置などの論理的な状態を保存します。
- `play` で保存されたペン画像を復元するには、同じペン解像度の
  レンダラが必要です。`--high-quality-pen` の設定は合わせてください。
- 実行途中の状態を保存するため、通常の `.sb3` へ変換するものではありません。

## 回帰テスト

```sh
cmake --build build --target xyo-cli -j
python3 tests/differential/hot_start.py build/xyo
# Linux + SDL2 のビルドなら CTest にも登録
ctest --test-dir build -R '^xyo-hot-start$' --output-on-failure
```

連続実行と保存・復元実行の差分を、変数・リスト・乱数・クローン・
音声待機・ペン最終画像で比較します。無関係なSB3や
不正なヒープポインタタグを含むセーブファイルを拒否するテストも含みます。
