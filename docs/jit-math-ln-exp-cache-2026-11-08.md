# MATH-008: bit-identical log/exp JIT tables (2026-11-08)

## Implementation and semantics

The pure numeric SSA emitter in src/jit/numeric_repeat_float_ssa.inc now
contains two guarded constant tables.

1. LN: A per-LLVM-module immutable array of 8193 doubles, indices 1..8192
   generated by calling jsnum::jsLog(double(index)) at JIT compile time.
   This is the SAME fdlibm-compatible routine used by xyo_log at runtime.
   Do not use std::log; it can differ in its final bit.

2. EXP: A per-LLVM-module immutable array of 51 doubles for x=k/10
   where k=0..50, generated with v8math::exp(k/10), the same implementation
   as runtime xyo_exp. Direct comparison found that std::exp differs by
   one ULP at x=1.7, 2.1 and 4.7. It was rejected.

A hit requires exact IEEE-754 equality to the guarded grid point.
Negative, fractional, out-of-range, neighboring-ULP, Infinity and NaN
values fall back to the original emitMathop call. Before any FPToUI,
a select replaces out-of-range operands with a safe in-range value
to avoid LLVM poison. Signed zero retains the original behavior.

Only JIT uses the tables; AOT always invokes the original runtime
helper to avoid cross-platform libm differences. The tables use
immutable module-level globals, reused for multiple math reporters.
Raw constant data is about 64 KiB (ln) plus 408 bytes (exp) per LLVM
module, plus optimizer/JIT overhead.

The only source edit outside the MATH-owned numeric SSA include is
one additional v8math.hpp include in src/jit/codegen.cpp. Other
agents' main codegen edits remain intact.

Both features are enabled by default on eligible JIT float SSA loops.
Rollback is available:
- XYO_JIT_LOG_TABLE=0
- XYO_JIT_EXP_TABLE=0
- The existing XYO_JIT_POW10_TABLE=0 controls the prior MATH-007 table.

## Paired measurements (same binary, CPU12, ABBA groups)

| Additional feature | Median ratio | Stable groups | Checksum |
| --- | ---: | ---: | ---: |
| ln integer table | 1.3348x | 8/8 | 718102 |
| exp tenths table | 1.3387x | 4/8 | 718102 |
| both together vs both disabled | 2.1189x | 2/8 | 718102 |

Only 2 combined groups satisfied the <=8% drift criterion, so the
combined ratio cannot be treated as a precise causal estimate.
Raw records: build/math008-log-abba.json, build/math008-exp-abba.json,
build/math008-both-abba.json.

The unmodified 47-kernel ScratchBench performance project completed
with BOTH tables OFF and BOTH tables ON in a previously verified binary
(build/math008-exp-xyo). All non-scheduler checksums were identical.
Math Exponential & sqrt yielded 57819.2 vs 116142.4 ops/ms (2.0087x)
in this sequential comparison; other Math kernels showed only minor
changes. Logs: build/math008-full-off.log, build/math008-full-both.log.

The median launch+run time for the ln-only 8-group ABBA test was
813.5 ms OFF vs 814.5 ms ON, with no substantial observed startup
penalty in that particular native execution environment.

  positive integers 1..8194 and 10000/100000 samples,
  ULP neighboring numbers, negative numbers, fractions, signed zero,
  infinities, NaN and tagged numeric/non-numeric strings. Warp/non-warp,

  all 51 tenths including the 3 glibc exp ULP mismatch inputs,
  ULP neighbors, negative and invalid inputs, signed zero, infinity,
  NaN, strings. All the same execution modes matched.
  Log: build/math008-exp-parity.log.

XYO_JIT_LOG_TABLE=1 and XYO_JIT_EXP_TABLE=1, the full ScratchBench
parity was 2123/2123 (100%) in each of HotSpot, Eager, Interpreter
and AOT. Log: build/math008-stable-snapshot-parity.log.
