## Implemented — indexed broadcast-and-wait

- `src/engine/runtime.cpp`: `startBroadcastAndWaitIndexed` consumes `broadcastReceivers` without constructing the generic one-entry map or re-matching hat fields; captures and returns exactly the started Thread* join handles, retaining old restart behavior and Scratch receiver order. Non-restarting hats snapshot the pre-existing thread set.
- `src/jit/rt.cpp` and `src/blocks/core.cpp`: both LLVM/JIT and Interpreter invoke the common `Runtime::startBroadcastAndWait` method instead of duplicating map creation.
- `XYO_BROADCAST_WAIT_INDEXED=0`: forces the legacy generic-hat dispatch path in the exact same binary for controlled A/B and debugging; default is indexed.
- `tests/unit/test_scheduler.cpp`: 32 receivers with 20 existing threads; test generic startHats, nonwaiting startBroadcast, and indexed startBroadcastAndWait. Verifies all remaining receivers are dispatched and no duplicates are created.
- `tests/bench/algos/scratchbench_probe.py`: standalone, unmodified workload probes for pingpong, fanwait, fanout and list_append.
- `tools/bench-rivals.ts`: machine-readable category and 47-item relative-rank analyzer.

### Paired A/B measurements

Same binary (`build-perf-all/xyo`), CPU 8 pinned, 8 alternating pairs, HotSpot, 30fps; per-run data: `build/perf-all-paired-results.json`.

| Workload | Old ops/ms | Indexed ops/ms | Ratio |
|---|---:|---:|---:|
| sched_pingpong | 539.58 | 568.58 | 1.0538× |
| sched_fanwait | 1832.13 | 1881.10 | 1.0267× |

Differences are small and per-run values varied widely, so treat them as candidate improvements, not guaranteed across systems. The original ScratchBench scheduler values remain a different full-suite measurement.

A separate event-driven scheduler toggle was also measured with exactly the same protocol. **`XYO_EVENT_SCHED=1` produced 97.09 ops/ms vs default 155.94 for sched_waituntil (0.623×)**. Do not enable this option by default based on idle-wait microbenchmarks alone.

## Next performance priorities

The largest individual gaps against rival highest scores were `list_append`, `sched_pingpong`, `math_arith`, `math_collatz`, `algo_sieve` and `sched_waituntil`. They need separate root-cause and native-code measurements rather than project-name-specific shortcuts. The current indexed broadcast change by itself does **not** meet the 47/47 goal. Numeric fast paths, scheduler scheduling rules and list storage should be benchmarked on whole projects as well as microbenchmarks.

IR-001, RT-001, and IR-002 own the shared Continuation/CallFrame/Host Effect ABI. This batch deliberately leaves those contracts unchanged. Worktree is shared and has substantial unrelated uncommitted changes. No commit or push was performed.
